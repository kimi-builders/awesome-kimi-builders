# AGENTS.md — For agents working in this repo

**English**(canonical) · [中文](./AGENTS.zh-CN.md)

## What this repo is

`awesome-kimi-builders` is the public awesome list of the kimi.builders community.
The external recommendations shown at <https://kimi.builders/awesome> source from
`data/entries/*.json` here; the README list sections are generated by
`scripts/build-readme.mjs` — **never hand-edit a generated section**.

## Layout

```text
data/entries/<slug>.json   one file per project (the only source of truth for entries)
data/README.md             entry schema (English canonical; zh companion alongside)
scripts/validate.mjs       data validation (zero deps: node scripts/validate.mjs)
scripts/build-readme.mjs   regenerates the list sections of BOTH READMEs
.github/workflows/ci.yml   validation + generation-drift check on PRs
CONTRIBUTING.md            human process (English canonical)
DATA-FLOW.md               how this repo feeds the kimi.builders site
```

## Language policy (hard rule)

**English is the canonical language; translations live in separate sibling files** —
never mix languages in one file. Pairs: `README.md` ↔ `README.zh-CN.md`,
`CONTRIBUTING.md` ↔ `CONTRIBUTING.zh-CN.md`, `AGENTS.md` ↔ `AGENTS.zh-CN.md`,
`DATA-FLOW.md` ↔ `DATA-FLOW.zh-CN.md`, `data/README.md` ↔ `data/README.zh-CN.md`.
Edit the English file first and update its Chinese sibling **in the same PR**;
more locales (e.g. `*.ja.md`) follow the same pattern. Code comments and commit
messages are in English.

## Working rules

1. **To change the list, edit `data/entries/` only** — one project per PR. Afterwards:
   ```bash
   node scripts/validate.mjs        # must be green
   node scripts/build-readme.mjs    # regenerates BOTH README list sections; commit the diff
   ```
2. **Entries stay bilingual** (the site renders both): every entry needs `descriptionZh`
   AND `descriptionEn` — factual, one sentence each, "what it does + the Kimi connection".
   No marketing tone, no superlatives, no emoji.
3. **Never invent projects**: everything listed must really exist at a public URL.
   **Never list abandoned/deprecated projects**, regardless of past quality — when a
   project's own README says it is winding down, it comes off the list.
4. `agents` only accepts ids from the shared registry (`data/README.md`, kept in sync with
   the site's `src/lib/agents.ts`); adding a brand means changing both repos together.
5. Git identity for this tree: `kimi.builders <git@kimi.builders>` — do not switch.
6. No dependencies: scripts use the Node standard library only (ESM, Node ≥20).
7. DATA-FLOW.md documents the site contract. Read it before touching the schema —
   breaking changes are a protocol upgrade: note it in DATA-FLOW.md first and get
   site-maintainer sign-off.
